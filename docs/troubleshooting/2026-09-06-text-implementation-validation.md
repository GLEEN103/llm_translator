# 최초 텍스트 구현의 검증 및 문제 해결

> 서버 기반 0.1 버전의 역사적 기록이다. 현재는 확장 설정 UI와 API 직접 호출로 전환했으므로 아래 서버·키 파일 안내를 사용하지 않는다. 현재 안내는 [확장 직접 호출 전환](2026-09-06-extension-direct-api.md)을 따른다.

- 관련 계획: [0003](../implementation-plans/0003-text-google-implementation.md)
- 상태: 아래 개발 중 문제 수정 완료. 실제 Chrome 설치·실제 API 호출은 미검증.

## Host 검사 테스트가 잘못된 결과를 반환

Node fetch로 Host를 바꿔 요청했을 때 테스트는 403을 기대했으나 200을 받았다. 테스트 클라이언트가 Host를 실제 연결 대상으로 다시 작성하여 의도한 공격 요청이 만들어지지 않았다. 원시 `http.request`로 Host를 지정하도록 테스트를 수정했고 서버의 거절을 확인했다. 서버 Host 검사를 완화하지 않았다.

## 인라인 요소 사이의 공백 유실

공백만 있는 텍스트 노드를 제외하면 `<span>Hello</span> <span>again</span>`이 붙어서 추출될 수 있었다. 표시된 인라인 공백은 유지하고 완성된 구간 전체가 공백인 경우에만 제외하도록 수정했다. 브라우저 DOM 테스트에서 `Hello again`이 유지됨을 확인했다.

## 확장 옵션 페이지의 메시지 송신자

송신자의 tab 유무로 옵션 페이지를 거절하지 않도록 수정했다. 대신 확장 ID와 정확한 popup/options URL로 확인한다. [Chrome MessageSender 규격](https://developer.chrome.com/docs/extensions/reference/api/runtime)에 따라 tab 정보가 있는 옵션 페이지도 처리하며, 해당 조건을 자동 테스트로 검증했다.

## 사용 중 오류 안내

| 증상 | 확인할 항목 |
| --- | --- |
| 로컬 서비스에 연결할 수 없음 | `npm start` 실행 상태와 43187 포트 충돌 |
| 연결 토큰 또는 확장 ID 오류 | ID 등록 재확인, 서버 재시작 후 새 토큰 입력 |
| API 키·모델 설정 필요 | 사용자 편집기에서 `.env.local` 설정 후 서버 재시작 |
| Google 인증 실패 | 키 권한·유효성. 키를 로그나 채팅에 붙여넣지 않음 |
| 모델 또는 요청 오류 | 사용 가능한 JSON 출력 모델 ID, `models/` 접두사 제거 |
| 응답 시간 초과 | 짧은 선택 영역으로 확인. 재시도 시 중복 과금 가능 |
| 번역 대상 없음 | 일반 웹페이지인지, 폼·iframe·숨김·이미지 내용인지 확인 |
| 원문 변경으로 제외 | 페이지에서 대상을 다시 수집하여 새 작업 실행 |
| 확장 연결 중단 | 확장 버튼에서 재시작. 확장 재로드 후에는 페이지도 새로고침 |

실제 원문·키·토큰 없이 오류 종류와 재현 조건만 기록한다.
