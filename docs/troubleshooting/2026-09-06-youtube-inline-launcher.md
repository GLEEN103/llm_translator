# YouTube 페이지 자막 번역 버튼 (0.10.0)

## 요구와 기존 제약

확장 아이콘을 열지 않고 좋아요 옆에서 자막 번역에 진입하도록 요청받았다. 기존 activeTab은 확장 호출 이후의 임시 권한이라 페이지 진입만으로 버튼을 자동 삽입할 수 없었다. [계획 0013](../implementation-plans/0013-youtube-inline-launcher.md)을 먼저 작성하고 YouTube 전용 정적 스크립트와 호스트 권한을 추가했다.

## 구현

현재 영상 작업 영역의 좋아요/싫어요 묶음 다음에 작은 버튼을 둔다. 확인한 실제 DOM은 `ytd-watch-metadata #top-level-buttons-computed`와 `segmented-like-dislike-button-view-model`이다. 구형 묶음 선택자도 처리하고 미확인 구조는 같은 작업 영역 끝에 배치한다. 홈/Shorts/플레이어 없음에서는 제거하며 SPA·DOM 재생성 후 버튼을 복원한다.

버튼 실제 클릭만 현재 탭·메인 문서·영상 검사 후 기존 패널을 연다. 동의/키가 빠져 있으면 설정 페이지를 안내한다. 같은 영상에서 패널을 다시 열면 ON·언어·결과를 유지한다. 자동 탐지·열기는 Google 번역을 시작하지 않는다.

## 검증

- 공개 YouTube 테스트 영상의 실제 작업 영역 DOM을 읽어 좋아요 묶음 구조를 확인했다. 페이지를 변경하거나 좋아요/공유를 실행하지 않았다.
- Node 테스트 106개 통과: 신규 진입의 송신 문서 고정, 타 탭 메시지 필드 무시, 외부 sender/iframe/영상 변경/오래된 문서 거절, 미설정/미동의 안내와 API 호출 없음 포함.
- 로컬 브라우저 fixture의 DOM 회귀 검사 8개 통과: 좋아요 뒤 배치, 중복 방지, 영역 교체, 좋아요 구조 누락 시 대체, 홈 제거, 홈→영상 복원, 영상 간 이동, 영역 없음 제거.
- 실제 클릭으로 페이지 버튼→OFF 패널 열기를 확인했다. ON으로 번역 후 접기→페이지 버튼 재클릭에서 ON 및 준비된 2문장이 유지되고 번역 요청은 1회로 유지됐다. 설정 필요/열기 오류 안내도 확인했다.
- 실제 Chrome 확장 설치에 따른 권한 부여와 YouTube/Google 전체 연동은 미검증이다. Google API 호출과 실제 키 열람은 수행하지 않았다. fixture는 모의 chrome API이며 제품 서버 의존성이 아니다.
- JavaScript 45개 구문·JSON·정적 주입/호스트 권한 검사 및 보안 schema v10 하네스를 통과했다.

## 버튼이 보이지 않을 때

0.10.0 확장을 새로고침하고 YouTube 페이지도 새로고침한다. Chrome에서 YouTube 사이트 접근이 허용됐는지 확인한다. 일반 watch 페이지에서 영상과 작업 버튼 영역이 로드되어야 표시된다. 영역 자체가 변경된 레이아웃은 기존 확장 아이콘의 자막 번역으로 열 수 있다. 새 권한은 www.youtube.com에 한정되며 다른 YouTube 서브도메인/Shorts/임베드 버튼은 지원하지 않는다.
