# 자막 OFF 첫 실행 후 수집 실패가 이어지는 문제 (0.10.1)

## 증상과 확인 범위

사용자는 YouTube 원문 자막을 켜지 않고 번역을 먼저 시도하면 페이지를 새로고침할 때까지 자막을 읽지 못한다고 보고했다. 코드에서 다음 복구 누락을 확인했다.

- 모듈 이름이 노출되면 비동기 트랙 선택의 완료를 확인하지 않고 즉시 reload를 한 번 호출했다.
- 정상 자막 응답이 없는 정체 상태에서 같은 호출을 반복했으며 captions 모듈 자체의 복구 경로가 없었다.
- 첫 목록 실패 후 같은 패널을 다시 열면 빈 목록을 유지한 채 패널만 펼쳤다.
- 일시적인 브리지 실패는 ON 컨트롤러의 자동 수집 재시도 대상에서 빠져 있었다.

위 조건은 모의 플레이어/브라우저로 검증했다. 사용자 Chrome·해당 실제 영상의 내부 상태를 직접 관찰해 단일 원인으로 확정한 것은 아니다.

## 해결

[구현계획 0014](../implementation-plans/0014-caption-cold-start-recovery.md)에 따라 모듈 준비와 선택 트랙 적용을 분리해 기다린다. 무응답 4초 뒤 captions 모듈만 최대 한 번 unload/load한다. 기존 전체 12초 관찰 제한·응답 크기 제한을 유지하고 영상/페이지를 재로드하지 않는다. 빈 events/제어 이벤트 응답은 수집 완료로 확정하지 않는다.

원래 트랙은 복사하여 참조 변경에 오염되지 않게 한다. 원문 자막 OFF를 기록하고 확장이 변경한 상태임을 확인한 경우에만 성공/실패 후 복원한다. 사용자 트랙 변경·자막/설정 메뉴 클릭을 감지하면 추가 변경을 멈춘다. 타이머와 fetch/XHR 관찰·클릭 리스너는 종료 시 정리한다.

빈 목록 상태에서 다시 패널을 열면 목록을 재수집하고 중복 목록 요청은 막는다. 브리지 실패는 기존 간격으로 ON 자동 재시도한다. 현재 안내는 반복적인 페이지 새로고침을 기본 해결책으로 요구하지 않는다.

## 검증 결과

- `npm test`: 113개 통과. 자막 OFF·지연 트랙 적용, 무응답 모듈 한 차례 복구, 빈 JSON 뒤 정상 응답, 실패 후 같은 페이지에서 재시도 성공, 사용자 변경 보호, 가변 트랙 객체의 원래 값 복원, ON 중 브리지 오류 복구를 포함한다.
- `npm run check`: JavaScript 45개·JSON·진입점/권한 검사 통과.
- PowerShell 하네스: 기존 schema v10/권한·보안 정책 통과.
- 실제 브라우저 DOMParser 기반 자막 XML/JSON 회귀 8/8 통과.
- 브라우저 모의 UI: 자막 없음 → 첫 목록 실패/ON 비활성 → 자막 가능 상태로 변경 → 같은 페이지의 자막 번역 버튼 재클릭 → 목록/ON 복구 → 2문장 번역 표시를 확인했다. 페이지 새로고침·패널 닫기는 수행하지 않았다.
- 실제 API 키 열람/Google 호출 없음. 실제 YouTube 플레이어와 Chrome 확장을 함께 실행한 검증은 남아 있다. 자막 미제공/접근 제한·플레이어 API 변경까지 성공을 보장하지 않는다.

## 사용 안내

0.10.1 코드를 적용하기 위해 확장과 열려 있는 YouTube 페이지를 한 번 새로고침한다. 이후 수집 일시 실패는 ON 상태에서 자동 재시도한다. 첫 목록 실패는 **자막 번역** 버튼 재클릭 또는 **목록 새로고침**으로 재시도할 수 있다. 원문 자막 OFF에서 시작해도 초기화를 시도하며 수집 도중 원문 자막이 잠시 보일 수 있다.

참고한 [YouTube IFrame API 문서](https://developers.google.com/youtube/iframe_api_reference)는 공개 플레이어 API의 기준이다. www.youtube.com 시청 페이지의 내부 loadModule/track 동작을 공식적으로 보장하는 자료로 해석하지 않는다.
