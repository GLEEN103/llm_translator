# 재생 직후 무반응처럼 보이는 UI 소실 — 0.11.3

## 재현과 원인

사용자는 영상 재생 직후 첫 클릭에서 UI가 나타나지 않고 팝업 호출도 간혹 실패하며 새로고침 후 복구한다고 보고했다. 이전 0018은 주입 대기/위치 문제를 다뤘으나 media 노드 수명은 그대로였다.

기존 render는 같은 영상이어도 video/player 노드가 교체·분리되면 close했다. OPEN_VIDEO는 이미 opened:true를 반환한 상태라 이후 UI 삭제는 실패 안내를 남기지 않았다. 모의 브라우저에서 OPEN 직후 30ms에 video를 교체했을 때 실제 패널 개수가 0이 되는 것을 확인했다. 같은 조건의 수정 후 패널 개수는 1이며 목록/설정이 유지됐다.

추가로 0 크기의 video에서는 host 전체를 숨겼고 수동 열기도 같은 숨겨진 표면을 복원했다. yt-navigate-start도 현재 영상 ID와 관계없이 패널을 삭제했다. 사용자 실제 YouTube에서 이 내부 이벤트가 발생하는지는 직접 계측하지 않았으므로 모든 간헐 오류가 이 한 원인이라고 단정하지 않는다.

## 수정

설정 패널을 현재 문서/영상 ID에 귀속시키고 자막만 안정된 media 노드에 연결한다. 노드 부재/0 크기에서는 화면 모서리에 준비 UI를 유지한다. 동일 player/video가 최소 크기를 충족해 200ms 안정되면 다시 연결하며 이전 media 이벤트는 해제한다. 토글/닫기/기존 ON·결과를 유지하고 대기 중에도 OFF는 가능하다.

대기 중 새 수집/번역과 자막 표시는 쉰다. 상태 응답을 기다리다 플레이어가 사라지는 경우도 수집 전 재확인한다. 최초 자막 목록은 준비 후 최대 3회 확인한다. 실제 영상 ID 변경/문서 종료는 기존 작업을 정리하며 다른 영상 자동 ON은 하지 않는다. launcher는 video가 잠깐 없다고 현재 영상의 작업 영역 버튼을 제거하지 않는다.

## 검증

- 수정 전/후 동일 OPEN 직후 교체: 패널 0개 → 1개, 오류 없는 UI 소실 복구.
- Shorts 실제 DOM 모의 자동 회귀 10/10 PASS: OPEN, 교체, 부재 중 UI, 대기 중 토글 양방향, 0 크기, 같은 ID 탐색, 다른 ID 정리, video 없는 최초 OPEN/가시 UI.
- ON 상태에서 노드 교체 후 4초 재생 위치의 자막 표시, 준비 중 요청 횟수 유지와 OFF 조작 확인. 실제 공급자 호출은 0회.
- Node 124/124, JS 48개 구문/JSON/manifest, 하네스 PASS. 원문/실제 키/개인정보 로그를 남기지 않았다.

실제 Chrome 확장 설치/YouTube 계정/Google API 종단 간 검증은 미실시다. 업데이트 적용을 위해 확장과 페이지를 한 번 새로고침한다. 재생 중 노드 교체에 대한 복구는 새로고침에 의존하지 않는다. [구현계획](../implementation-plans/0019-playback-start-panel-lifecycle.md).
