# 2026-09-06 — 자막 목록은 있지만 본문이 비어 있는 문제

## 재현

사용자 제공 영상 ID `-SRYHQyg-58`. 기존 0.8.0에서 `CAPTIONS_UNAVAILABLE` 안내가 나타났다.

- 공개 watch 페이지 요청: HTTP 200, player status OK, 영어 `en` / `asr` 트랙 1개 확인.
- 기존 방식인 baseUrl + fmt=json3 직접 요청: **HTTP 200, 응답 본문 0 bytes** 재현.
- 같은 영상의 YouTube 화면에는 실제 자막 문자가 표시되었다. 초기 로딩 중에는 “자막 사용 불가”가 나타나지만 이것만으로 자막 미제공을 판단하면 안 된다.
- 셸 진단은 쿠키·API 키 없이 공개 페이지와 선택 트랙만 요청하고 상태/크기/언어만 출력했다. 서명 URL·토큰·본문은 저장하지 않았다. 최초 샌드박스 네트워크 EACCES 후 이미 허가된 공개 주소에 대한 제한적인 네트워크 실행을 승인 검토 도구로 수행했다.

확인한 원인은 **기존 수집 코드가 직접 재요청한 응답에 의존했고, 빈 응답에서 다른 정상 플레이어 경로를 시도하지 않은 것**이다. YouTube 서버가 빈 응답을 반환하는 내부 이유나 사용자의 브라우저가 동일한 서버 분기를 탔는지까지 단정하지 않는다.

## 수정

0.8.1에서 직접 요청 실패 시 해당 영상의 실제 플레이어가 요청/수신하는 자막 응답을 12초 동안만 관찰한다. 자막 모듈 준비를 기다리고 선택한 트랙으로 자막 재로드를 요청한다. 원래 요청/응답은 변경하지 않고 자막 본문 복사본만 제한적으로 읽는다. 외부 서비스·토큰 생성·클라이언트 위장·로컬 서버를 도입하지 않는다.

다른 영상/언어/variant·자동 번역(tlang) 응답은 적용하지 않는다. 크기는 2 MiB로 제한하고 종료 시 hooks, 타이머, 이벤트 리스너를 정리한다. 원래 자막 설정은 사용자가 도중에 바꾸지 않았음을 확인할 수 있을 때만 복원한다.

실제 플레이어의 JSON3와 XML srv3/legacy를 처리한다. XML을 기기에서 파싱하며 DTD/ENTITY/HTML 오류문은 거절한다. API 키와 모델 호출 경로는 변경하지 않는다.

## 새로운 오류 구분

| 코드 | 의미 / 조치 |
| --- | --- |
| CAPTIONS_BRIDGE_FAILED | 확장 수집 스크립트 실행 실패 또는 브리지 대기 초과. 확장과 페이지 모두 새로고침 |
| CAPTIONS_PLAYER_UNAVAILABLE | 플레이어 자막 모듈/API 준비 안 됨. 영상 재생과 YouTube 자막 활성화 후 재시도 |
| CAPTIONS_PLAYER_TIMEOUT | 선택한 원문 언어의 정상 플레이어 자막 응답을 12초 안에 받지 못함. YouTube에서 같은 언어 선택 후 재시도 |
| CAPTIONS_INVALID / CAPTIONS_TOO_LARGE | 응답 형식/타임코드 또는 크기 한도 문제 |

## 검증 및 한계

- Node 93개 테스트, JavaScript 40개 구문/JSON/권한 검사, 보안 하네스 통과.
- 직접 빈 응답→native 응답 fallback, fetch/XHR 후킹 원복, 응답을 소비하지 않는 복사, 다른 영상/언어·초과 본문 거절, 타임아웃, 사용자 트랙 변경 보존, 자막 모듈 초기화 대기를 테스트했다.
- 실제 브라우저 DOMParser 검사 **8/8 통과**: srv3/legacy XML, 밀리초·소수초, append, HTML/DTD/형식 오류와 JSON3. 최초 테스트의 1.2+2.4 엄격 동등 비교는 부동소수점 오차로 실패하여 테스트를 1e-9 허용 오차로 수정한 뒤 통과했다.
- 이 환경에서는 실제 Chrome 확장 설치 후 새 native 수집 경로와 Google API 번역을 끝까지 검증하지 않았다. 공개 영상 직접 요청 오류 재현과 모의 회귀 테스트를 실제 통합 성공으로 간주하지 않는다. 사용자의 실제 API 키를 열람/사용하지 않았다.

사용 시 Chrome 확장 관리에서 **0.8.1로 새로고침**하고 해당 YouTube 페이지도 새로고침한다. 영상 재생·자막 활성화 후 팝업에서 다시 번역한다. 실패가 계속되면 표시된 새 오류 코드로 수집 단계가 구분된다.
