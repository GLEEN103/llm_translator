# 나중에 로드된 자막이 자동 번역되지 않는 문제와 표시 설정

## 증상과 원인

처음 로드된 자막 번역이 끝나면 사용자가 다시 실행해야 이후 구간이 처리됐다. 이전 video-content.js는 처음에만 VIDEO_CAPTIONS를 읽고 미번역 배치가 없어지면 종료했다. 동일 설정의 준비된 구간이 있으면 재실행에서도 새 수집을 건너뛰었다. 표시 설정도 고정되어 있었다.

## 수정 (0.9.0)

[계획 0012](../implementation-plans/0012-continuous-captions-and-style.md)에 따라 ON/OFF 컨트롤러를 분리했다. ON은 수집 완료 후 최소 10초마다 새 구간을 확인하고 기존 구간과 병합하며 미번역 문장만 구조화 요청한다. 읽기/번역을 직렬화하고 텍스트별 캐시로 응답 ID 재사용 혼선을 막는다. OFF는 타이머·공급자 요청을 취소하고 늦은 결과를 무시한다. 같은 작업에서 다시 ON하면 기존 번역을 재사용한다.

일시적 수집/네트워크 실패는 간격을 늘려 자동 재시도하고 인증/설정/동의/예산 오류는 OFF로 전환한다. 광고·숨겨진 탭에서는 새 작업을 쉰다. 언어 변경·영상 이동·닫기에 맞춰 기존 작업을 무효화한다.

배경/글자 불투명도, 서체, 글씨 크기, 세로 위치, 가로 정렬을 즉시 적용하고 미리보기·기본값 복원을 제공한다. 표시 설정만 trusted local에 저장한다. 범위/필드/서체 enum을 background에서도 검사하며 임의 CSS/URL을 받지 않는다. 큰 자막이 설정 조작부 위에 겹치지 않게 패널 표시 순서도 조정했다.

## 검증 결과

- `npm test`: 103개 통과. 새 구간 자동 번역, 동일 문장 중복 전송 방지, 같은 시각의 수정 문장, OFF/늦은 응답 폐기, OFF→ON 중 읽기 직렬화, 재시도·rate limit·설정/인증 오류, 숨김/광고 일시 정지, 캐시 재사용, 병합 한도, 표시 설정 검증·저장·문서 grant를 포함한다.
- `npm run check`: JavaScript 43개, JSON·진입점·권한 범위 통과.
- PowerShell 하네스: schema v9·문서/코드 분리·비밀정보 정책 통과. 실제 비밀정보를 읽지 않았다.
- 로컬 더미 브라우저: ON 첫 요청에 2문장, 후속 구간 로드 후 추가 조작 없이 두 번째 요청에 새 문장 1개만 번역하여 10초 구간에 표시했다. 반복 자막 확인이 20회까지 늘어도 번역 요청은 2회로 유지됐다. OFF 후 10초 이상 동안 두 횟수 모두 유지되고 자막이 숨겨졌다.
- 표시 설정: 배경 35%, 글자 70%, 명조, 36px, 세로 25%, 오른쪽 정렬을 실제 입력으로 변경하고 화면/설정 값 및 닫기→재열기·페이지 재로드 후 복원을 확인했다. 기본값 복원과 접은 패널에서도 자막 표시를 확인했다. 제품 저장은 broker 자동 테스트로, 브라우저 fixture 저장은 sessionStorage 모형으로 검증했다.
- 실제 Google API 호출 0회. 실제 Chrome에 설치한 확장과 YouTube/Google을 연결한 전체 통합 검증은 수행하지 않았다. 실제 계정의 자막 응답 형태/제공 시점과 모델 지연·비용은 별도 검증 대상이다.

## 사용 시 조치와 한계

확장과 YouTube 페이지를 새로고침한 뒤 이번 버전 전송 동의를 처리한다. 원문/목표 언어를 골라 번역 ON으로 켜면 이후 로드 구간도 자동 확인한다. 수집 주기와 공급자 지연 때문에 탐색 직후에는 준비 시간이 생길 수 있다. API 오류로 OFF가 되면 설정/한도를 확인한 뒤 다시 켠다. 자막을 제공하지 않거나 읽기가 제한되는 영상까지 지원을 보장하지 않는다. 정상 플레이어 응답을 기다리는 동안 YouTube 원문 자막 설정이 일시 변경될 수 있다. 로컬 서버는 제품에 추가하지 않았다.
