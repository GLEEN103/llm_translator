# 본문 레이아웃과 작은 요청 다수 문제

관련 계획: [0007](../implementation-plans/0007-context-menu-layout-batching.md).

## 원인과 수정

이전 dom.apply는 원문 조상에 display:block·padding·margin을 강제한 span을 추가했다. 번역 노드가 grid/flex 항목이 되거나 인라인 요소의 흐름과 셀 크기를 바꾸는 구조였다. 기존 Text 노드의 값만 변경하고 원문을 작업 메모리로 복원하도록 수정했다. 태그·속성·CSS·링크 이벤트·자식 수가 보존된다. 번역 후 페이지가 값을 변경하면 복원 시 그 변경을 유지한다.

기존 전송도 JSON 배열이었지만 8구간·6,000자 상한으로 요청 수가 많았다. 64구간·12,000자로 묶음을 확대하고 Google responseJsonSchema에 translations의 ID·텍스트 배열을 명시했다. 반환 순서에 의존하지 않고 ID로 연결하며 잘못된 묶음은 적용하지 않는다.

## 검증과 한계

- 자동 테스트: 짧은 요소 40개는 1묶음, 65개는 2묶음. 문자 한도·긴 구간·응답 순서 반전·누락·중복·알 수 없는 ID 검증.
- 브라우저 DOM: grid/flex/table/inline 구조·스타일·이벤트 보존과 원문 복원, 페이지 후속 변경 보호 등 29개 검사 통과.
- 모의 UI: 54구간(중복 제거 후 53구간)을 1회 요청으로 번역하고 모두 해당 위치에 적용했다. 복원과 선택 스냅샷 실패 후 재시도도 확인했다.
- 원래 문제가 발생한 사용자 사이트와 실제 Google 호출 지연은 미검증이다. 번역 길이로 인한 자연스러운 줄바꿈은 유지한다. 동적 페이지가 번역 후 재렌더링하면 새 작업이 필요할 수 있다.
- Chrome 메뉴 설치·클릭은 API 모의 테스트로 검증했다. 실제 Chrome 설치 환경의 우클릭 메뉴 통합 검증은 남아 있다.
