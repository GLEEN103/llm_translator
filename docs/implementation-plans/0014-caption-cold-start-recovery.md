# 0014 — 자막 OFF 첫 실행과 새로고침 없는 복구 (0.10.1)

## 증상과 확인된 코드 문제

YouTube 원문 자막 OFF에서 번역을 먼저 실행하면 이후에도 수집하지 못한다고 보고됐다. 기존 native fallback은 captions 모듈 이름이 보이면 track 설정과 reload를 같은 순간 한 번 호출한다. 비동기 track 적용 완료를 기다리지 않고, 응답이 없는 캐시/모듈 상태도 재초기화하지 않는다. 처음 실패한 목록을 가진 기존 패널을 다시 열어도 같은 패널을 펼치기만 한다. 이 코드 경로의 모의 재현과 실제 사이트 통합 재현은 구분한다.

## 수정 계획 (코드 변경 전)

- 기존 12초 관찰 안에서 모듈 준비 → 트랙 적용 확인 → reload를 단계적으로 수행한다. 원문 자막 OFF/모듈 지연·트랙 비동기 적용을 지원한다.
- 응답이 없으면 한 호출당 최대 1회 captions 모듈만 unload/load하여 정체된 상태를 복구한다. 영상 재로드·재생 위치·인증/서명 URL 조작은 하지 않는다. 지원 API가 없으면 기존 제한 안에서 실패 안내한다.
- 시작 트랙을 복사해 보관하고 원문 OFF 상태도 기록한다. 복구·종료 중 사용자의 트랙/자막 변경을 덮어쓰지 않는다. 성공·실패·시간 초과 모두 네트워크 관찰/타이머를 정리한다. 비어 있는 JSON 자막 응답은 성공으로 확정하지 않고 제한 안에서 계속 기다린다.
- 목록 읽기 실패 뒤 다시 패널을 열면 목록을 재수집한다. 재시도 가능한 브리지 실패는 ON 컨트롤러가 기존 간격으로 재시도한다. 새로고침을 강제하는 고정 오류 안내를 현재 복구 방식에 맞춘다.
- 권한·키 정책·서버 구성·데이터 전송 범위는 유지한다.

## 검증과 변경 대상

youtube-player-captions.mjs, video-content.js, video-session.js, core 오류 문구, 버전, 회귀 테스트·fixture, 기획/구조/트러블슈팅 문서. 지연 트랙 적용, OFF→수집→OFF 복원, 모듈 초기화 후 응답, 첫 실패 뒤 같은 페이지 재시도, 사용자 변경 보호, 빈 응답·타임아웃 정리를 모의 테스트한다. 기존 Node/브라우저 XML·UI/구문/하네스를 확인한다. 실제 키/API는 사용하지 않는다.

## 결과

- 0.10.1 구현 완료. 트랙 적용 확인·한 차례 자막 모듈 복구·OFF 복원·사용자 변경 보호·빈 응답 대기·실패 목록 재수집과 브리지 자동 재시도를 적용했다.
- Node 113개, 브라우저 XML/JSON 8/8, JavaScript 45개 및 하네스 통과. 브라우저에서 목록 실패 후 동일 페이지 재열기로 복구하고 번역 2문장을 표시했다.
- 실제 Google API 호출은 없으며 실제 Chrome/YouTube 통합 재현은 미검증이다. 모의 재현 범위와 남은 한계를 [트러블슈팅](../troubleshooting/2026-09-06-caption-cold-start.md)에 기록했다.
- 전체 계획·제품 범위·README·설치·실행 구조·보안 문서에 반영했다. 서버·권한·키 저장·정책 schema는 유지한다.
