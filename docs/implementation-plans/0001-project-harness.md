# 0001 — 프로젝트 작업 하네스 구성

> 초기 구성의 역사적 기록이다. 서버 전용 키·서버 디렉토리·환경변수 템플릿 관련 내용은 [0004](0004-extension-direct-api.md)에서 폐기했다. 현행 작업 규칙은 AGENTS와 전체 계획을 따른다.

- 상태: 구현 및 문서 반영 완료
- 목적: LLM API 기반 Chrome 확장 프로그램의 개발 규칙과 보안 경계를 먼저 구성한다.
- 허가 범위: `C:\work\program\chrome_translator` 및 그 하위 경로만 열람·수정한다.

## 요구사항

1. 문서와 실제 코드를 분리한다.
2. 기획, 구현계획, 트러블슈팅, 구조 문서를 각각 별도 디렉토리에 둔다.
3. 구현계획 작성 → 구현 → 구현사항 문서 반영 순서로 작업한다.
4. 별도로 허가되지 않은 경로, 외부 경로를 가리키는 링크, 사용자 전역 설정을 열람하지 않는다.
5. API 키 등 민감 정보의 보관·접근·배포 규칙을 별도로 구성한다.

## 변경 계획

- 루트 `AGENTS.md`: 작업 순서, 열람 범위, 문서 관리, 비밀정보 취급 규칙.
- 루트 `README.md`: 프로젝트 진입점과 검증 명령.
- `docs/planning/`: 제품 범위와 미결정 항목.
- `docs/implementation-plans/`: 변경 전 계획과 변경 후 결과.
- `docs/troubleshooting/`: 장애 기록 방식.
- `docs/architecture/`: 저장소 구조와 보안 설계.
- `src/extension/`, `src/server/`: 확장 프로그램과 비밀정보를 사용하는 서버의 코드 공간.
- `config/security-policy.json`, `.env.example`, `.gitignore`: 보안 정책과 비밀정보 제외 설정.
- `tools/verify-harness.ps1`: 필수 구조와 보안 설정의 일관성 검사.

## 구현 범위와 제외 범위

이번 변경은 개발 하네스만 구성한다. 번역 기능, Chrome 확장 실행 코드, API 연결, 서버 실행 코드와 배포는 이후 구현계획에서 다룬다. 실제 API 키를 요구하거나 저장하지 않는다.

## 검증 계획

- 생성 파일이 허가된 프로젝트 디렉토리 안에 있는지 확인한다.
- PowerShell 검증 도구로 필수 파일과 보안 정책을 확인한다.
- 기본 실행 정책이 스크립트를 차단하면 검증 프로세스에만 `RemoteSigned`를 지정한다. 사용자·시스템 정책은 수정하지 않으며 조직 정책으로 계속 차단되면 중단하고 한계를 기록한다.
- 기획·구조·트러블슈팅 문서를 확인하고 이 계획의 상태와 구현 결과를 갱신한다.

## 구현 결과

### 반영 사항

- 루트 작업 규칙과 진입점 문서를 작성했다. 사용자가 제공한 gstack 관리 블록은 그대로 보존했다.
- 문서 네 종류를 각각의 디렉토리에 분리하고 제품 코드·서버 코드·개발 도구·공유 설정의 위치를 구분했다.
- 프로젝트 밖 정보 열람 제한과 비밀정보 파일에 대한 별도 열람 허가 규칙을 명시했다.
- 서버 전용 API 키 정책, 빈 환경변수 템플릿, 비밀정보 Git 제외 설정을 추가했다.
- 구현계획 작성 → 구현 → 구현사항 문서 반영 순서를 작업 규칙에 고정했다.

### 검증 결과

- `powershell -NoProfile -ExecutionPolicy RemoteSigned -File tools/verify-harness.ps1`: 종료 코드 0, PASS.
- 필수 디렉토리·파일, 보안 정책, 비밀정보 제외 패턴, 환경변수 템플릿의 빈 값을 확인했다.
- 생성 대상은 모두 프로젝트 내부 경로다. 외부 메모리·스킬·설정 파일과 실제 비밀정보는 읽지 않았다.
- 초기 스크립트 실행 차단과 프로세스 한정 해결 방법을 [트러블슈팅 문서](../troubleshooting/2026-09-06-powershell-execution-policy.md)에 반영했다.
- 기획·구조·보안 문서에 실제 구현 상태와 미구현 항목을 기록했다.

### 남은 한계

- 확장 프로그램, 서버, API 연결과 런타임 보안 기능은 아직 구현하지 않았다.
- 하네스의 경로 제한은 에이전트 규칙이며 별도 OS 접근 통제를 구성한 것은 아니다.
- 검증 도구는 설정 일관성 검사이며 비밀정보 전체 탐지나 Git 제외의 실제 적용 검사를 대신하지 않는다. Git 초기화와 배포도 이번 작업에 포함하지 않았다.
