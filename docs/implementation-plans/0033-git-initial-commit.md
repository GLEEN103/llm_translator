# 0033 Git 초기화와 GitHub 최초 게시

## 목적과 범위

- 현재 0.18.0 프로젝트를 Git 저장소로 초기화하고 최초 커밋한다.
- 사용자가 지정한 `https://github.com/GLEEN103/llm_translator.git`를 origin으로 설정하고 main 브랜치를 푸시한다.
- 소스·문서·공유 설정·검증 도구만 추적한다. 테스트 Chrome 프로필, 임시 결과, 로그, 의존성, 실제 비밀정보 파일은 제외한다.

## 절차와 보안

1. 제외 규칙과 추적 후보 경로를 점검하고 줄바꿈 규칙을 설정한다.
2. 원격 refs를 확인한다. 원격에 기존 이력이 있으면 강제 덮어쓰지 않고 보존하는 방식으로 통합한다.
3. Git을 초기화하고 명시적인 프로젝트 경로만 스테이징한다. 심볼릭 링크/정션·민감 경로·대형 파일·비밀 문자열 패턴을 값 노출 없이 검사한다.
4. 최초 커밋 후 main을 정상 푸시하고 원격 커밋 ID와 로컬 상태를 확인한다. 기존 Git 인증을 사용하며 키/토큰/전역 설정 파일을 직접 읽거나 저장하지 않는다.

## 검증과 구현 결과

- 최근 제품 검증은 자동 테스트 270개, JavaScript 78개 구문·설정 검사 및 보안 하네스 통과다. 제품 코드는 이번 작업에서 변경하지 않는다.
- `main`으로 Git을 초기화하고 지정된 저장소를 `origin`으로 등록했다. 원격 refs 조회 결과 기존 브랜치가 없음을 확인했다.
- `.gitattributes`에 텍스트 LF 정규화와 PowerShell 작업 파일 CRLF 규칙을 추가했다. 기존 `.gitignore`의 비밀정보·테스트 프로필·임시 파일 제외 규칙을 유지했다.
- 추적 후보 165개(약 1 MiB)에서 링크, 1 MiB 초과 개별 파일, 민감 경로 및 검사한 자격증명 패턴이 발견되지 않았다. 이 패턴 검사는 모든 종류의 비밀정보 부재를 보장하지는 않는다. 실제 비밀정보 파일은 열람하지 않았다.
- `tools/verify-harness.ps1`을 재실행해 통과했다. 제품 코드 변경이 없어 제품 테스트는 이번 Git 작업에서 반복하지 않았다.
- 실행 계정과 폴더 소유자가 다른 환경에서는 이 프로젝트만 명령별 `safe.directory`로 지정했다. 전역 Git 설정은 변경하지 않았다.
- 최초 커밋과 정상 푸시 후 원격/로컬 커밋 ID 일치 및 작업 트리 상태를 완료 보고에서 확인한다.
