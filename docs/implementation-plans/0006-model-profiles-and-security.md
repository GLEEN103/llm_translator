# 0006 — 출시일 정렬·모델별 키 영구 저장·보안 정책

- 상태: 0.4.0 구현·모의 검증·문서 반영 완료. 실제 Chrome 설치/업데이트·계정 호출은 미검증.
- 사용자 요청: 모델을 출시년도 기준 최근순으로 정렬하고 API 키를 세션이 아닌 모델별로 저장한다. API 키 보안 정책을 수립한다.

## 설계와 범위

1. Google models.list에는 출시일 필드가 없다. 공식 출시 기록으로 확인한 정확한 모델 ID별 날짜를 번들 데이터로 관리해 API 조회 결과에 결합한다. 날짜 내림차순(년도 우선), 같은 날짜는 ID순. 미확인 모델·가변 latest 별칭은 날짜를 추측하지 않고 '출시일 미확인'으로 마지막에 표시한다. 목록의 실제 제공 모델은 계속 API에서 가져온다.
2. 공급자+정확한 모델 ID별 API 키와 공개 모델 정보, 활성 모델을 trusted chrome.storage.local에 보관한다. 브라우저 재시작·확장 업데이트 후 유지한다. 목록 조회 임시 키·카탈로그·요청·호출 예산은 session에만 둔다. 다른 모델의 키로 번역을 대체하지 않는다.
3. 설정에 저장 모델 선택·활성화, 선택 모델 키 교체/삭제, 전체 키 삭제를 제공한다. 재시작 후 저장 모델은 목록을 다시 조회하지 않아도 활성화할 수 있다. 새 모델 저장·키 교체에는 그 키로 조회한 카탈로그 검증이 필요하다. 키 입력을 비우면 해당 대상 모델에 이미 저장한 키만 유지하며 다른 모델 키를 암묵적으로 복사하지 않는다.
4. 키 저장·모델 전환·삭제는 직렬화하고 설정 버전을 바꿔 진행 중 번역을 취소한다. 삭제·전환은 임시 카탈로그도 제거해 오래된 요청으로 키가 복구되지 않게 한다. 이전 session-only 키는 자동 영구 이관하지 않으며 사용자가 모델별 저장으로 전환한다.
5. 보안 정책: local/session 모두 TRUSTED_CONTEXTS, 키 재표시·응답 포함·로그·sync·내보내기·원격 코드 금지, 고정 Google HTTPS 헤더 전송, 사용자 키만 허용. local은 암호화 금고가 아니며 OS/프로필 접근자나 침해된 확장 환경에는 보호를 보장하지 않는다. 복호화 키를 함께 저장하는 형식적 암호화를 추가하지 않는다. 노출 시 공급자에서 폐기·재발급하고 확장에서 교체/삭제하도록 안내한다. 로컬 서버는 추가하지 않는다.
6. 버전 0.4.0, 정책 v4로 갱신하고 현행 기획·구조·설치·보안·트러블슈팅을 반영한다. 설치/업데이트별 최초 동의는 유지한다.

## 검증

- 출시일이 모델명 순서보다 우선하는지, 같은 날짜·미확인·별칭·잘못된 ID 정렬 확인.
- 재시작/업데이트 후 두 모델의 서로 다른 키 보존·선택한 모델 키만 전송·다른 모델 키 자동 복사 방지.
- 단일/전체 삭제·키 교체·활성화 중 취소·지연 응답·조회 실패·저장 실패·외부 송신자 차단.
- 상태·오류·content 응답에 키 비노출, trusted 접근 설정 실패 시 처리 중단.
- 가짜 키와 모의 API만 사용하는 자동 테스트·설정 브라우저 검증·하네스 검사. 실제 사용자 키는 열람하지 않는다.

## 근거

- [Google Model 규격](https://ai.google.dev/api/models): 출시일 필드 없음.
- [공식 출시 기록](https://ai.google.dev/gemini-api/docs/changelog): 모델 ID별 출시 날짜.
- [Chrome storage](https://developer.chrome.com/docs/extensions/reference/api/storage): local 수명과 접근 수준.

## 결과

- 공식 기록에서 확인한 37개 정확한 모델 ID의 날짜를 `model-releases.mjs`에 등록하고 API 목록과 저장 모델 목록에 같은 정렬을 적용했다. 출시일/년도 최근순이며 같은 날짜는 ID순, 미확인·가변 별칭은 마지막이다. API가 제공하지 않은 모델을 목록에 임의 추가하지 않는다.
- `profiles.mjs`에 공급자+모델별 영구 저장·활성화·단일/전체 삭제를 구현했다. local의 한 레코드에 프로필과 활성 상태를 함께 저장하고, 저장 실패는 안전한 오류로 반환한다.
- `broker.mjs`는 활성 슬롯의 키만 번역에 사용한다. 새 모델의 빈 키 저장을 거절하고 프로필 변경 시 요청·임시 카탈로그를 취소한다. 콘텐츠·상태 응답에는 키를 포함하지 않는다.
- 설정 UI에 저장 모델 선택·사용·키 삭제, 출시일 목록, 키 보관 수명 및 보안 정책을 추가했다. 키는 입력칸에 재주입하지 않으며 조회/저장/전환을 분리했다.
- 보안 정책 v4와 AGENTS·README·기획·전체 계획·실행 구조·설치·트러블슈팅을 갱신했다. 0005는 0.3.0의 역사적 기록으로 표시했다.

| --- | --- |
| `npm test` | 44개 통과. 출시일/별칭/동일 날짜 정렬, 두 모델의 다른 키 유지·전송·교체·삭제·동의·저장 실패·접근 제한 실패 포함 |

개발 중 단일 삭제 테스트가 빈 모델 ID의 잘못된 요청을 만들어 NOT_CONFIGURED 대신 INVALID_REQUEST를 받았다. 실제 삭제 전 패널처럼 유효한 이전 모델/설정 버전을 보내도록 테스트를 수정하여 삭제 후 다른 키로 대체 전송하지 않는 것을 확인했다.

실제 사용자 키를 읽거나 공급자 API를 호출하지 않았다. 브라우저 검증은 가짜 키·모의 API와 재로드 유지용 fixture 저장소이며 실제 Chrome local 수명·업데이트 통합 검증을 대신하지 않는다. 출시일 데이터는 2026-09-06 공식 기록 확인 시점의 번들 데이터라 신규 미확인 모델은 후속 갱신이 필요하다.

키 영구 저장은 구현했지만 별도 저장 암호화는 제공하지 않는다. trusted 접근 제한과 키 비노출·동기화/로그 금지를 적용하며 OS/프로필 접근자·침해된 확장 환경에 대한 한계는 [API 키 보안 정책](../architecture/security.md)에 명시했다. 로컬 서버는 추가하지 않았다.
