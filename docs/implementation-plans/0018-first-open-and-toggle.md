# 0018 — 최초 열기 정체와 페이지 버튼 토글 (0.11.2)

## 조사와 구현계획

- 최초 진입의 문서 확인/제품 파일 주입은 injectImmediately 없이 executeScript를 호출한다. Chrome 공식 규격은 기본 document_idle 대기다. 페이지가 로드 중이면 진입이 지연될 수 있고 launcher의 20초 타임아웃만으로는 background 대기를 끝내지 못한다. https://developer.chrome.com/docs/extensions/reference/api/scripting
- 일반 영상은 화면 밖 video도 표면으로 선택한다. 패널은 그 사각형에 고정되므로 아래쪽 페이지 버튼에서 최초로 열어도 화면 밖에 생성될 수 있다. 최초 open은 showPanel도 호출하지 않는다.
- 문서 확인/명시적 패널 파일 주입을 즉시 실행하고 각 주입/메시지 단계를 8초로 제한한다. 자막 진입은 필요한 video 모듈만 주입한다. 문서 고정/URL/동의/grant 보안 검사는 유지한다. 실패 후 재시도 가능하게 한다.
- 패널 초기화 오류는 불완전 state/host를 정리하고 안전한 실패 응답을 보내 다음 클릭을 허용한다. 새 패널/기존 복원 모두 화면 밖이면 해당 영상을 화면 안으로 이동한다.
- 페이지 버튼은 동일 영상의 기존 패널이 보이면 숨기고, 숨겨져 있으면 복원한다. 내부 API toggle(id)는 기존 작업 유무를 반환하고 팝업의 restore는 항상 열기로 유지한다. 닫기/토글 OFF는 번역 ON/결과를 유지한다. 전체 숨김 후 토글 ON은 표시를 복원한다.
- 최초 열기 대기 중 UI가 이미 생성되면 버튼을 계속 사용할 수 있게 하고, 뒤늦은 성공 응답이 사용자 토글 결과를 뒤집지 않게 한다. 버튼의 aria-expanded는 실제 패널 상태를 따른다.

## 검증·범위

로드가 끝나지 않은 모의 scripting에서 기존 최초 열기 정체를 재현하고 즉시 주입/문서 고정·타임아웃 뒤 재시도를 Node로 검증한다. 브라우저 watch/Shorts에서 최초 열기, 반복 토글, 닫기 후 토글, ON·결과 유지, 화면 밖 영상의 패널 복원, 영상 이동 후 새 OFF 작업을 확인한다. 실제 키는 사용하지 않는다. 권한/키 정책/schema/서버 구성은 변경하지 않는다. 구현 후 관련 현행 문서와 결과를 반영한다.

## 결과

- 0.11.2 구현 완료. 즉시·비디오 전용 주입/단계별 대기 제한, 불완전 UI 상태 정리, 화면 밖 영상 스크롤 복구와 페이지 표시 토글을 적용했다. 팝업은 항상 열기로 유지했다.

- 모의 브라우저: 초기화 1회 실패 후 새로고침 없는 재시도, watch/Shorts 반복 토글·ON/결과 유지, 닫기/전체 숨김 후 복원 PASS. 화면 밖 watch video(bottom -614px)가 최초 열기 후 overlay와 함께 top 135px로 들어오는 것을 확인했다. 지연된 OPEN 응답이 있는 Shorts에서도 토글을 확인했다.
