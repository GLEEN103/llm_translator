# 0011 — YouTube 빈 자막 응답 수정 (0.8.1)

## 재현과 원인

사용자 영상 `-SRYHQyg-58`의 공개 watch 응답에서 영어 ASR 트랙이 확인되었다. 기존 방식대로 baseUrl에 fmt=json3를 붙여 요청하면 HTTP 200 / 0 bytes가 재현된다. 실제 YouTube UI에서는 자막이 나타난다. 자막 없음과 직접 재요청 실패를 동일시할 수 없다. 어떤 서버 검증이 빈 응답을 유발하는지는 확인되지 않았다.

## 변경 계획 (코드 변경 전)

- 원래 직접 요청을 유지하되 실패하면 현재 YouTube 플레이어가 정상적으로 받은 timedtext 응답을 수집한다. 비공개 토큰 생성/우회·다른 클라이언트 위장·외부 자막 서비스·로컬 서버는 추가하지 않는다.
- MAIN world에서 해당 영상의 자막 요청만 일시 관찰한다. fetch/XHR 응답의 제한된 복사본만 읽으며 요청 URL/헤더/쿠키는 확장으로 반환하거나 저장하지 않는다. 최대 2 MiB. 페이지 요청/응답 자체는 수정하지 않는다.
- 선택한 원문 트랙을 플레이어에 적용하고 captions reload를 요청하여 정상 플레이어 경로로 자막을 가져온다. 언어/영상/타임코드를 검증하고 다른 트랙 응답을 혼동하지 않는다. 필요하면 사용자가 YouTube에서 자막을 켜도록 구체적으로 안내한다.
- 관찰기는 시간 제한/완료 시 정리한다. 원래 플레이어의 자막 선택/표시 상태를 가능한 경우 복원하되 사용자가 작업 중 바꾼 설정은 덮어쓰지 않는다. 설정 복원을 보장할 수 없는 경우 표시 변경을 UI와 문서에서 알린다.
- JSON3 외 실제 플레이어가 사용하는 XML timedtext(srv3/legacy)도 기기에서 파싱한다. 지원되지 않는 응답을 오류로 표시하고 상세 단계 코드(빈 응답/관찰 시간 초과/형식)를 추가한다.
- 기존 문서 grant·동의·키 보안·단일 자막 읽기·결과 검증을 유지한다. 관찰 데이터는 메모리에서만 취급한다.

## 검증

- 공개 영상에서 직접 요청 200/0 bytes 재현 기록. 실제 플레이어 자막 제공 확인.
- 빈 직접 응답 뒤 정상 플레이어 응답 수집, fetch/XHR 정리, 다른 영상/언어·초과 응답 거절, XML/JSON3, 타임아웃·모델 키 비노출 회귀 테스트.
- 기존 자동/구문/하네스 검사. 실제 공급자 호출은 하지 않는다. 실환경에서 확인한 범위와 모의 검증을 분리해 기록한다.

## 결과

0.8.1 수정 완료. 직접 요청의 200/빈 본문을 별도 내부 코드로 구분하고 플레이어 응답 관찰로 재시도한다. 자막 모듈 준비를 기다린 뒤 원문 트랙 선택 및 reload를 요청한다. 같은 영상/언어/kind/variant의 번역되지 않은 timedtext 응답만 허용한다. fetch는 원래 Promise/응답을 그대로 유지하고 복사본만 읽으며 XHR은 loadend에서 응답을 관찰한다. 관찰 제한 12초, 브리지 실행당 16초, content의 자막 수집 응답 대기는 40초다.

JSON3와 XML srv3/legacy를 처리한다. XML DTD/ENTITY·HTML 오류문·잘못된 타임코드는 거절한다. 종료 시 관찰기/타이머/이벤트 리스너를 정리하며 사용자 트랙 변경이 없을 때만 기존 트랙을 복원한다. 복원 여부를 확인할 수 없으면 UI에서 원래 자막 표시가 바뀔 수 있음을 알린다.

검증: Node 테스트 93개 통과, JavaScript 40개/JSON/권한 검사 통과, 하네스 schema v8 검사 통과. 실제 브라우저 XML/JSON3 검사 8개 통과. 실제 영상의 직접 요청 실패(200/0 bytes)와 화면 자막 존재는 확인했지만, 실제 Chrome 확장 안에서 새 플레이어 응답 관찰→Google 번역까지의 성공은 검증하지 않았다. 테스트는 실제 API 키를 사용하지 않았다.

공식 근거: [YouTube Player API captions reload](https://developers.google.com/youtube/iframe_api_reference#onApiChange)는 자막 데이터 재로드를 지원한다. watch 페이지의 track 선택/내부 구현은 공개 iframe API가 보장하는 범위를 넘어 버전 영향을 받을 수 있으므로 별도 오류 코드와 한계를 유지한다. 상세 기록: [자막 빈 응답 수정](../troubleshooting/2026-09-06-youtube-empty-response.md).
