# 0019 — 재생 시작과 설정 패널 수명 분리 (0.11.3)

## 조사·구현 전 계획

사용자 추가 재현 조건은 재생 직후 클릭, 페이지 버튼/일부 팝업 모두 무반응, 새로고침 후 복구다. 이전 0018은 주입 대기/위치를 다뤘지만 재생 시작의 DOM 교체는 검증하지 않았다.

- 현재 render는 video/player 노드 교체·일시 분리에서 즉시 close한다. OPEN_VIDEO는 이미 opened:true를 반환하므로 직후 교체가 발생하면 오류 안내 없이 UI가 사라질 수 있다. 크기가 0이면 host 전체를 숨기며 수동 재열기도 같은 숨겨진 video에 연결한다. yt-navigate-start도 영상 ID와 무관하게 패널을 닫는다.
- 먼저 모의 재생 시작에서 OPEN 성공 직후 video 교체와 크기 0을 재현한다. 패널은 현재 영상 ID/문서에 귀속시키고 실제 자막 표시만 안정된 media 노드에 연결한다. 동일 영상의 잠깐 비어 있는/교체되는 player는 패널을 제거하지 않고 대기 상태로 표시한다. video가 없거나 크기가 0일 때도 가시 대체 위치의 설정 UI를 먼저 제공한다.
- 표면이 200ms 안정되면 현재 노드에 다시 연결한다. 대기 중 자막/새 번역 요청을 쉬고, 안정화 후 같은 영상 작업만 이어간다. 실제 URL 영상 변경/문서 종료는 즉시 정리한다. 이전 media 이벤트는 해제하고 새 video에 바인딩한다.
- launcher는 동일 영상의 잠깐 사라지는 video 때문에 버튼을 제거하지 않게 한다. 현재 영상 작업 영역만 사용하고 페이지 홈/다른 영상은 별도로 처리한다. 기존 표시 토글/닫기/전송 권한은 유지한다.
- 자막 목록을 player 안정화 후 읽어 첫 재생 초기화와 충돌을 줄인다. 제한된 목록 재시도는 현재 영상·기존 grant에서만 수행하고 ON 전에는 번역하지 않는다.
- 실패 판별을 위해 UI에서 준비 중/실패를 명시한다. 비밀정보·원문·URL 로그나 새 서버/호스트 권한은 추가하지 않는다. 실제 계정/키 사용은 하지 않는다.

## 검증

기존 구현에서 OPEN 직후 동일 영상 video 교체 시 성공 응답 후 UI가 사라지는지 브라우저에서 확인한다. 수정 후 노드 부재/0크기/교체/정상화, 토글/닫기, 이전 영상 제거, 안정화 중 API 요청 없음과 반복 media 이벤트 정리를 검증한다. Node 전체/구문/하네스 검증 후 현행 문서에 실제 결과와 한계를 반영한다.

## 결과

- 0.11.3 구현 완료. 설정 패널을 문서/영상 ID에 연결하고 media 부재/0 크기/교체는 준비 UI를 유지하도록 분리했다. 200ms 안정화, 동적 media 이벤트 재연결, 같은 ID 탐색 이벤트 유지, 실제 ID 변경 정리, launcher 보존을 적용했다.
- 기존 코드에서 OPEN 직후 30ms video 교체로 패널 개수 0을 확인했다. 수정 후 동일 조건에서 패널 1개/설정 유지. 실제 사용자 Chrome에서 같은 내부 이벤트가 일어났는지는 미확인이다.
- Shorts 브라우저 모의 수명 회귀 10/10 PASS. video 없는 최초 호출·0 크기·분리·교체·토글·같은/다른 ID 이동을 포함한다. ON 후 교체된 video의 4초 위치에 맞는 번역 자막, 준비 중 신규 요청 중지와 OFF 조작도 확인했다.
- Node 124/124 PASS. 신규 binding 안정화/ID 종료 검사와 상태 응답 대기 중 플레이어 소실 시 수집 보류 검사를 포함한다. JS 48개 구문/JSON/manifest 검사·하네스 PASS.
- 실제 공급자 호출 0회. 실제 Chrome 설치/YouTube/Google 종단 간 연동은 미검증이다. 원문/키/URL 진단 로그·호스트 권한·서버 추가 없음. 정책 schema v11 유지.
- README·현행 기획/구조/보안/사용법·트러블슈팅 갱신 완료.
