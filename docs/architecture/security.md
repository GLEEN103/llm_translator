# API 키 보안 정책 — v5

## 0.18.0 형식 재시도와 영상 번역 저장 (schema18)

사용자 요청으로 영상 번역문을 기기에 지속 보관한다. `chrome.storage.local`의 `TRUSTED_CONTEXTS`에 영상 ID·범위/원문 SHA-256·성공 번역문만 저장한다. 원문 문자열·영상 URL/제목·타임코드·픽셀/음성·API 키·원시 공급자 응답은 이 캐시에 저장하지 않는다. 번역문은 평문이며 해시는 프로필 접근자로부터 내용을 보호하는 암호화 수단이 아니다. 동기화/외부 캐시 서버는 사용하지 않는다.

최근 30개 영상/4 MiB를 상한으로 사용 순서에 따라 정리하고 options에서 전체 삭제한다. 캐시 적중에도 현재 영상·문서 grant·동의·설정 일치를 검사하며 콘텐츠에는 요청한 원문의 번역만 반환한다. 캐시 전체 읽기/임의 쓰기 메시지를 제공하지 않는다. 버전별 동의 안내와 자막 UI에 저장 사실, 설정 화면에 저장 범위와 삭제 방법을 표시한다.

JSON/스키마 오류는 최대 3회 재시도하고 모두 기존 RPM·문자 예산·usage를 적용한다. 최종 형식 오류는 실패 묶음만 제외해 자막 ON을 유지한다. 네트워크/시간 초과·거절·불완전 응답·인증/예산 실패에는 이 규칙으로 재시도하지 않는다. 표시 로그는 시각·고정 오류 코드·횟수·구간 수만 최대 100행 보관하며 원문/모델 원시 출력/스택/키를 포함하지 않는다. 아래 이전 버전의 무재시도·임시 자막 결과 설명에는 이 절을 우선 적용한다.

## 0.17.0 병렬 요청 정책 (schema17)

모든 탭·활성 번역 공급자·이미지 요청·Google 재시도에 공통 동시 5개/최근 60초 60회 제한을 적용한다. 시도 시각은 trusted session에 보존하며 broker의 직렬 잠금 안에서 검사·예약한다. 원문 문자 예산과 이미지 횟수 예산은 유지한다. OpenAI 전용 Worker도 최대 5개로 제한한다.

본문·부분·자막은 최대 5개 요청의 처리가 끝난 뒤 다음 차례 전 5초 대기한다. 로컬 `CLIENT_BUSY`/`CLIENT_RATE_LIMIT`은 원문을 전송하기 전에 거절하며 content가 기다린 뒤 재시도한다. Google의 응답 확인된 429/503 재시도도 제한에 산입하므로 첫 시도 후 두 번째 시도가 로컬 한도에 걸릴 수 있다. 한도 대기 자체는 새로운 API 전송/토큰 사용 기록을 만들지 않는다. 실제 API에 전송한 요청은 취소해도 과금 철회를 보장하지 않는다.

API 키 저장/전달·버전별 동의·Kie 비활성 정책은 그대로다. 아래 이전 버전의 동시/요청 간격 기록에는 이 절을 우선 적용한다.

## 0.16.0 OpenAI 직접 연동 (schema16)

API 키를 `openai:<exact-model-id>`로 분리하여 trusted local에 보관한다. 모델 목록은 고정 `https://api.openai.com/v1/models`에 해당 키의 Authorization 헤더로만 요청한다. API 목록과 번들 지원 목록의 교집합만 저장할 수 있으며 다른 공급자의 키·카탈로그를 사용할 수 없다. 저장 키 재표시·동기화·내보내기는 계속 금지한다.

텍스트/선택한 자막과 검증된 이미지 픽셀은 고정 `/v1/responses`로 전송한다. 이미지 URL·전체 화면·타임코드·영상/음성은 보내지 않는다. `store:false`로 응답 객체 저장을 비활성화하며 도구/검색/대화 이력을 보내지 않는다. 이 옵션은 공급자의 모든 보안/남용 감시 로그 보존까지 없앤다는 보장은 아니다. [OpenAI 데이터 정책](https://developers.openai.com/api/docs/guides/your-data).

긴 응답을 위해 background가 선택한 키를 생성별 UUID URL과 실제 context로 검증한 OpenAI 전용 포트/작업 Worker 메모리에 일시 전달한다. 일반 runtime 응답·content script·웹페이지로 키를 보내지 않는다. Worker는 고정 엔드포인트·모델·store/stream 설정·입출력 크기를 검사한다. 종료/취소/단절 시 Worker와 키 참조를 정리하며 유휴 문서를 닫는다. 요청은 180초, UI는 200초, 동시 작업은 0.17.0 기준 최대 5개다. 전송 후 실패한 요청을 자동 반복하지 않고 고정 오류만 안내한다.

사용량은 input_tokens, output_tokens, reasoning_tokens, cached_tokens, total_tokens의 검증된 숫자만 기록한다. 기존 통계의 출력은 확인된 추론 토큰을 제외하고 추론 열에 따로 합산한다. 제공되지 않은 값은 미확인이며 원문/키/원시 응답을 통계에 저장하지 않는다. API 호스트 하나를 추가하고 Google의 권한/전송, Kie 사용 중지, 서버 없는 구성을 유지한다.

## 0.15.2 Kie 사용 중지

Kie는 레거시 코드와 기존 키·통계만 보존한다. UI에서 공급자 선택을 비활성화하고 background에서 목록/가격 조회·키 저장·모델 활성화·번역을 차단한다. 기존 활성 Kie도 실행 불가능하며 Google 설정을 사용자가 직접 선택해야 한다. 기존 키의 개별/전체 삭제는 가능하다. 정책 schema15의 Kie 상태를 legacy-disabled로 명시하고 allowSelection/allowRequests=false로 설정했다. 기존 고정 호스트와 offscreen 권한은 보존 코드에 맞춰 유지하지만 사용 중지 경로에서 외부 호출은 없다. 다음 전송 예외는 현재 실행되지 않는 레거시 설계다.

## 0.15.1 trusted Kie 전송 예외 (schema15, 레거시)

영구 키 저장 정책 v4를 유지하며 background만 저장소의 키를 조회·선택한다. Kie의 긴 응답을 위해 선택된 키를 검증된 offscreen 전용 포트와 해당 문서의 요청별 Worker 메모리에 일시 전달한다. 포트는 확장 ID·생성마다 새 UUID fragment를 포함한 정확한 문서 URL·확장 origin·탭 없음을 확인한다. 현재 생성 시도가 유지되는지 확인하고 getContexts의 실제 OFFSCREEN_DOCUMENT가 같은 URL/origin, tabId=-1, documentId를 갖는지 검증한다. Chrome이 sender.documentId를 생략할 수 있으므로 제공된 경우에만 실제 문서 ID와 추가 대조한다. nonce는 문서 종료 시 폐기하며 키·원문을 포함하지 않는다. 일반 runtime 메시지/웹페이지/content script로 키를 브로드캐스트하지 않는다.

Worker는 번들에 지정된Kie 번역URL만 POST하며 credentials:omit/redirect:error/no-store와 입력128KiB/응답256KiB 제한을 강제한다. background가 동의·grant·모델revision·예산·사용량을 처리한다. 최대2개 Worker,180초 요청,진행중20초pulse만 허용하고 성공/실패/취소/단절 시 종료한다. 유휴문서를 닫으며 키·원문·응답 로그나 새영구저장은 없다. Chrome116/offscreen 권한을 추가하고 새호스트·서버는 추가하지 않는다. 아래0.14.x 기록의25초/background직접Kie호출은 이 변경으로 대체한다.

0.14.4는 Kie의 HTTP 500/524 및 클라이언트 타임아웃에서 자막 ON을 OFF로 전환해 같은 요청의 자동 반복을 중단한다. 오류 본문은 기존 크기 제한으로 읽고 숫자 usage와 code/error.code의 정확한 524 여부만 사용한다. 원문/원시 오류/키/식별자를 로그·저장소·오류 메시지에 추가하지 않는다. 고정 API 경로·키 보관·배치·25초 제한·정책 schema14를 유지한다.

0.14.3의 구조화 출력 요청은 기존 Gemini 3.8의 고정 Kie 경로와 같은 원문·구간 ID 범위만 사용한다. 출력 스키마를 추가하며 키·호스트 권한·동의/저장 정책은 변경하지 않는다. 빈 출력/일반 텍스트/JSON 오류를 구분할 때도 응답 내용과 원시 구문 오류 메시지를 노출·저장하지 않는다. 스키마 거절 후 자동 대체 호출은 없다.

0.14.2의 Kie 응답 진단은 고정 오류 코드만 사용자에게 전달한다. 키·원문·응답·URL 진단 로그나 저장 항목을 추가하지 않는다. 전체 JSON 코드블록 제거와 Gemini 3.8 native text 정규화 뒤에도 ID/구조/길이 검증을 유지하고 도구 호출·thought 출력을 적용하지 않는다. 형식 오류는 자막 ON 작업을 OFF로 종료하며 자동 유료 복구 요청을 추가하지 않는다. 기존 숫자 사용량만 검증 실패 시에도 집계한다. 키 정책 v4·보안 schema14·권한·전송 범위는 유지한다.

적용 버전: 확장 0.14.0, 키 저장 정책 v4 유지, 전체 보안 설정 schema v14. Google과 kie.ai의 키를 공급자·모델별로 분리한다. YouTube 페이지 버튼을 자동 표시하며 번역 ON 동안 선택한 자막을 계속 확인·번역한다. 자막 표시 설정과 내용이 없는 토큰 사용 통계를 영구 보관한다. 이전 세션 전용 키 정책은 [0006](../implementation-plans/0006-model-profiles-and-security.md)으로 변경한다.

통계에는 API 응답에서 정규화한 입력/출력/추론/전체/캐시 숫자와 제공 건수만 남긴다. 음수·문자열·비정수·안전 범위 초과 값과 나머지 응답 필드는 버린다. 합산은 JavaScript 안전 정수 상한을 넘지 않는다. 원문·번역문·픽셀·API 키·URL·영상 ID·요청 헤더는 통계에 보관하지 않는다. 외부 분석 서비스·동기화·내보내기는 없다. content script에는 통계 조회·삭제 권한을 주지 않고 승인된 팝업/통계에도 pending 임의 ID를 반환하지 않는다. 시작 시도 수는 영속 저장하지만 응답 미수신/저장 오류/worker 종료 후의 실제 사용량은 보장할 수 없으므로 미확인으로 표시한다. K/M 축약은 화면에만 적용한다. 공급자 미제공 값은 0으로 추정하지 않고 kie.ai의 금액·credit 정보는 저장하지 않는다.

Chrome local은 브라우저 재시작·확장 업데이트 후에도 유지하고 확장 제거 시 삭제된다. 접근 제한은 local/session 양쪽에 먼저 적용하며 실패하면 요청을 중단한다. [Chrome storage 규격](https://developer.chrome.com/docs/extensions/reference/api/storage)

키는 공급자와 정확한 모델 ID를 결합한 슬롯(`google:<model>` 또는 `kie:<model>`)에 저장한다. 기존 Google 슬롯 형식은 유지한다. UI의 저장·교체는 선택 모델만 수정한다. 저장된 모델 활성화에는 API 조회가 필요 없으며 해당 슬롯의 키만 사용한다. 활성 모델을 삭제하면 번역 불가 상태가 되고 다른 공급자/모델 키로 자동 전환하지 않는다. 새 모델에 키를 비워 저장하면 다른 모델의 키를 복사하지 않고 거절한다.

이전 session-only 설정의 키는 자동 영구 이관하지 않는다. 0.4.0 전환 시 사용자가 설정에서 키와 모델을 저장한다. 이후에는 재시작·업데이트 후 재입력할 필요가 없다.

## 입력·출력·전송 정책

- 공개 가격은 정확한 options 페이지에서만 `KIE_PRICES`로 조회한다. 고정 `https://api.kie.ai/client/v1/model-pricing/page`에 Chat·페이지 번호·고정 크기만 POST하고 키/쿠키/원문/설정 모델은 보내지 않는다. 18초·페이지당 512 KiB·최대 10페이지/1,000행과 중복 병합·30초 최소 간격을 적용한다. worker 메모리에 검증된 숫자·모델 ID·조회 시각·오류 상태만 두고 local/session/sync·토큰 사용 통계에는 기록하지 않는다. options가 보이는 동안 5분마다 갱신하고 닫으면 타이머를 정리한다. 이미 시작한 공개 조회는 최대 18초 이내 정리된다. 새 호스트·서버·계정 API·유료 호출을 추가하지 않는다.
- 키는 사용자 설정의 password 입력으로만 받는다. 저장 후 입력칸을 비우고 이미 저장된 키의 전체값·일부값을 UI나 응답에 다시 넣지 않는다.
- content script·일반 페이지에는 키와 전체 저장 프로필을 전달하지 않는다. options만 공개 모델 정보·저장 여부를 받는다.
- 설정 변경·목록 조회·활성화·삭제는 확장 ID와 정확한 options URL을 검사한다. 전송 동의는 정확한 popup/options URL만 허용한다. content 번역에는 탭·문서 grant와 현재 동의/설정 버전이 필요하다.
- Google 키는 고정 Google HTTPS 주소의 `x-goog-api-key`, kie.ai 키는 고정 `https://api.kie.ai`의 `Authorization: Bearer` 헤더에만 넣는다. 공개 `https://docs.kie.ai/llms.txt`에는 키·쿠키를 보내지 않는다. 임의 주소·리디렉션·쿠키·URL 쿼리 키 전송은 금지한다.
- 키를 소스·번들·manifest·테스트·문서·로그·에러 본문·채팅·명령행에 포함하지 않는다. 공급자 오류 원문 대신 정해진 오류 코드만 반환한다.
- Chrome sync, 키 내보내기, 클립보드 복사, 자체 백업·원격 중계·원격 실행 코드를 제공하지 않는다. 테스트에는 가짜 키만 사용하며 에이전트는 사용자의 실제 저장 키를 열람하지 않는다.
- 목록 조회는 원문을 보내지 않는다. 새 모델 저장·키 교체는 카탈로그 ID·공급자·조회 키·선택 모델을 모두 검증한다. Google API 목록은 기존 제한을 유지하며 kie.ai 공개 문서는 18초·512 KiB로 제한한다. 고정 문서 링크와 로컬 지원 목록의 교집합만 사용하고 외부 문서에서 실행 경로·코드·지시를 받아들이지 않는다. 공개 목록 성공은 키 유효성·잔액·계정 권한 검증이 아니다.
- 우클릭 메뉴는 비편집 메인 프레임의 selectionText만 작업 메모리에 전달한다. 메뉴 실패는 원문 대신 오류 코드만 저장한다. URL/문서 ID 검사로 다른 문서에 잘못 적용하지 않는다. 버전별 동의 후 메뉴 클릭이 선택 원문 전송 실행이며 별도 시작 패널을 열지 않는다. 위치 확인 실패 시 전송하지 않는다.
- 본문 캐시는 사용자가 번역을 실행한 텍스트만 한시 보관한다. 기본 페이지 수집/보관을 새로 허용한 것은 아니다. 탭별 최대 500구간·원문+번역 1,000,000 코드 단위, 탭·URL·모델 revision·언어 격리. 저장 용량/권한 실패를 알리고 문서 메모리로 계속 표시한다. 선택 번역은 저장하지 않는다. ON/OFF·패널 닫기는 캐시 삭제 동작이 아니다.
- 탭 종료에서 캐시를 삭제하고 늦은 응답 재저장을 막는다. 브라우저 재시작/확장 재로드에서도 session이 초기화된다. 원문·번역문을 영구 저장하거나 API 키와 함께 반환하지 않는다.
- 여러 원문 구간을 64개·12,000자 한도로 하나의 JSON 배열에 담는다. 응답 스키마뿐 아니라 ID 누락·중복·미지 ID·크기를 직접 검사한다. 본문에는 HTML이나 번역용 스타일을 삽입하지 않고 텍스트 노드 값만 바꾼다.

## 변경·삭제·노출 대응

이미지 인식은 0.7.0부터 사용자가 선택한 Google 멀티모달 모델에서 수행한다. 버전별 최초 동의 문구에 이미지 픽셀 전송과 기기 내 캡처/자르기를 포함한다. 동의 후 이미지 메뉴 클릭이 실행이며 매번 별도 동의를 받지 않는다. 식별할 수 없는 이미지·다른 프레임·변경된 문서·종료된 imageToken은 전송하지 않는다.

API에는 PNG/JPEG 픽셀과 목표 언어만 보낸다. PNG/JPEG로 재인코딩하여 원본 EXIF/파일 메타데이터를 전달하지 않는다. 이미지 URL·쿠키·페이지 본문·전체 화면은 모델에 보내지 않는다. 다른 출처 이미지를 임의 URL fetch로 재다운로드하지 않고 화면 crop으로 처리한다. 전체 화면은 crop 처리에만 쓰며 이미지 사각형의 화면 픽셀만 반환한다. 반투명 이미지의 사각형 안에 보이는 배경 등은 화면 crop에 포함될 수 있다.

이미지 요청에는 최대 4 MiB/2048px·세션 50회·기존 분당/동시 요청 제한을 적용한다. 이미지에 적힌 지시를 실행하지 않으며 HTML 결과도 텍스트로 표시한다. 외부 공급자의 인식 정확성/보관 정책은 확장이 통제하지 않는다. 실제 이미지·API 키로 에이전트 검증을 수행하지 않는다.

저장·활성화·삭제는 직렬화한다. 진행 중 요청을 취소하고 임시 카탈로그를 제거한 뒤 저장 프로필을 변경한다. 설정 버전 검사는 오래된 번역과 재시도를 차단한다. 실패한 저장/삭제는 성공으로 보고하지 않고 재확인을 안내한다.

**선택 모델 키 삭제**는 해당 슬롯만, **모든 모델 키 삭제**는 전체 프로필과 활성 모델을 제거한다. 동의·세션 예산은 유지한다. 브라우저가 관리하는 디스크·백업·기록 매체의 물리적 완전 삭제까지 보장하지 않으며, 여기서 삭제해도 공급자의 API 키 자체는 폐기되지 않는다.

노출이 의심되면 해당 Google/kie.ai 계정에서 키를 폐기하고 사용량을 확인한 뒤 새 키를 발급한다. 새 키로 모델 목록을 조회해 해당 모델 슬롯을 교체한다. 같은 키를 여러 모델에 직접 저장했다면 해당 슬롯을 모두 교체하거나 전체 삭제 후 재등록한다. 실제 키를 문제 보고에 첨부하지 않는다.

사용자 소유 프로젝트의 필요한 API 권한과 사용 한도를 사용하며 공용 개발자 키를 번들에 배포하지 않는다. 공용 기기에 영구 저장하지 않도록 UI에서 안내한다.

## 보호 범위와 한계

확장은 저장 키를 별도로 암호화하지 않는다. trusted local 저장은 일반 페이지·content script의 직접 접근을 차단하지만 OS/브라우저 프로필 접근자·개발자 도구·악성 프로그램·침해된 확장 코드로부터 키를 완전히 숨기지 않는다. [Chrome 보안 안내](https://developer.chrome.com/docs/extensions/develop/security-privacy/user-privacy)

자동 복호화용 키를 암호문과 함께 두는 방식을 안전한 금고로 설명하지 않는다. OS 금고·사용자 암호 기반 잠금은 현재 구현 범위가 아니며 로컬 서버를 추가하지 않았다. `config/security-policy.json`은 선언이고 실제 강제 근거는 `broker.mjs`, `profiles.mjs`, 공급자 코드 및 테스트다.

원문은 사용자가 번역을 실행할 때 활성 Google 또는 kie.ai에 전송하며 개인정보가 포함될 수 있다. kie.ai 선택 시 중개 플랫폼을 통해 선택 모델로 전달됨을 버전별 동의에 안내한다. 이미지 픽셀은 Google만 지원하며 kie.ai에서는 캡처·API 호출 전에 차단한다. 공개 이미지 URL 생성·파일 업로드는 제공하지 않는다. 이 확장은 공급자의 보관 정책을 통제하지 않는다. 원문/LLM 출력은 비신뢰 데이터이며 실행 가능한 HTML로 해석하지 않는다. 예산은 문자/호출 단위 제한이고 금액 상한은 아니다.

## YouTube 자막 전송과 접근 정책 (schema v11)

- 버전별 최초 1회 동의에 자막 텍스트 전송을 포함한다. 같은 버전에서 번역 실행마다 동의를 다시 받지 않는다. 목록 확인 뒤 사용자가 원문 트랙·목표 언어를 선택하여 ON으로 켜면 해당 영상의 새 자막 구간도 자동 전송한다. UI에 이를 표시하며 다음 영상/새 문서에서는 OFF로 시작한다.
- 활성 Google 또는 kie.ai에는 자막 텍스트와 세그먼트 ID·목표 언어 등 기존 번역 규격만 보낸다. 영상 URL/ID·제목·타임코드·음성·영상·YouTube 쿠키·자막 서명 URL은 보내지 않는다.
- YouTube 자신의 자막을 읽을 때만 해당 페이지의 same-origin 인증 상태를 사용한다. 쿠키를 직접 읽거나 확장으로 복사하지 않는다. 공급자 호출은 기존 credentials:omit과 background 키 보관을 유지한다.
- activeTab/scripting을 유지하며 0.10.0부터 정확한 `https://www.youtube.com/*` 호스트 권한과 그 메인 프레임의 정적 버튼 스크립트를 추가한다. 아이콘 호출 없이 버튼을 표시하고 클릭 후 기존 MAIN 자막 브리지를 실행하기 위한 범위다. 전체 사이트/YouTube 서브도메인·downloads·cookies·webRequest 권한은 추가하지 않는다. MAIN world에는 영상 ID·트랙 인덱스만 전달한다. MAIN 반환값은 웹페이지와 같은 비신뢰 데이터로 검증한다.
- 원시 응답 2 MiB, 이벤트 5,000개, 원문 100,000자 및 최대 24시간 타임코드로 제한한다. 자동자막·번역은 명령으로 실행하지 않는다. 요청/응답·트랙·타임코드는 작업 메모리만 사용하며 local/session/sync/log에 보관하지 않는다. 키 저장 정책은 변경하지 않는다.
- YouTube가 자막을 제공하지 않거나 서명/권한/CSP/형식으로 거절하면 실패를 안내한다. 외부 자막 서비스, 인증 우회, 임의 URL 요청, 음성 인식으로의 자동 대체는 없다. 로컬 서버도 추가하지 않는다.

## 정상 플레이어 자막 응답 관찰 (0.8.1 도입, 0.9.0 유지)

직접 요청이 비어 있으면 현재 선택 영상의 정상 플레이어 자막 응답만 메모리에서 관찰한다. 12초 제한, 2 MiB 제한과 문서/영상/언어 검증을 유지하며 request headers와 cookies는 수집하지 않는다. YouTube 인증 토큰을 생성하거나 임의 서명/클라이언트로 재요청하지 않는다. fetch/XHR 요청 동작은 그대로 두고 복사/이벤트 관찰로 처리한다. 종료 또는 시간 초과에 관찰을 정리한다. 자막 수집 도중 UI를 닫은 경우에도 이미 시작한 MAIN 호출은 최대 12초 내 정리되며 늦은 결과는 content generation 검사로 폐기한다. API 키 저장·외부 번역 전송 범위는 변경하지 않는다.

## 연속 실행과 표시 설정 (0.9.0)

자동 작업은 현재 문서 grant·영상 ID·동의·모델 revision에 한정한다. 유휴 상태는 최대 5초 간격으로 확인하고 수집 완료 뒤 최소 10초를 기다린다. 0.17.0부터 번역은 최대 5개 묶음을 병렬 처리하고 한 차례 완료 후 최소 5초 대기한다. 기존 일시 오류는 최대 60초 간격으로 재시도하며 모든 실제 번역 시도에 공통 분당/세션 예산을 적용한다. 인증·설정·예산 실패와 OpenAI 전송 오류는 OFF로 전환한다. 숨김 탭·광고 중 새 작업을 쉬며 OFF/작업 종료는 타이머·모든 공급자 요청을 취소하고 늦은 응답을 무시한다. 이미 시작한 MAIN 수집과 전송된 API 요청의 완전 철회/과금 취소는 보장하지 않는다.

표시 설정은 원문이나 비밀정보와 분리된 `videoAppearance`에만 저장한다. 메시지에서 추가 필드·임의 CSS·외부 URL/서체·범위 밖 숫자를 거절한다. 문서 grant 없는 페이지는 조회/수정할 수 없다. 표시 설정 저장은 API를 호출하거나 모델별 키 레코드를 읽지 않는다. ON 여부·자막 텍스트는 영구 저장하지 않는다. 호스트 권한과 로컬 서버 구성은 변경하지 않는다.

## YouTube 페이지 버튼 (0.10.0)

0.10.2에서는 sender 문서 URL의 경로를 현재 영상으로 간주하지 않는다. 정확한 YouTube 출처·메인 프레임·documentId를 검사한 뒤 현재 tabs.get URL 및 고정 문서 location.href로 inline 진입을 확인한다. 후속 자막 요청도 출처·현재 탭 영상·문서 grant를 검사한다. SPA의 이전 주소만으로 거절하지 않되 임의 출처/영상/문서 접근을 새로 허용하지 않는다. 버튼 색/크기는 기기 내 DOM 계산값만 이용하며 권한·키·전송 정책은 변경하지 않는다.

0.10.1의 자막 OFF 초기화 복구는 기존 MAIN 관찰 12초 안에서만 수행한다. 응답이 없을 때 captions 모듈 재초기화는 한 호출당 최대 한 번이며 영상 자체를 재로드하거나 인증 토큰·서명 URL을 변경하지 않는다. 시작 OFF/트랙은 소유권 확인 뒤 복원하고 관찰 중 사용자 변경은 덮어쓰지 않는다. 브리지 실패 재시도에도 기존 ON·문서·영상·분당/세션 예산을 유지한다. 권한/전송 범위/키 저장/정책 schema는 변경하지 않는다.

사용자 요청으로 정확한 YouTube 사이트 권한을 추가했다. 정적 스크립트는 DOM에서 URL/플레이어/작업 영역을 확인하고 버튼만 삽입한다. 탐지만으로 grant 발급·자막 수집·키 조회·Google 호출을 하지 않는다. 실제 클릭 메시지에서 Chrome이 제공한 sender.id/tab/frameId/documentId/url을 확인하며 메시지에 든 임의 주소/탭을 신뢰하지 않는다. 문서 고정 확인 후 동의/설정을 검사하고 기존 패널을 연다. API 키는 반환하지 않으며 미설정/미동의는 고정 options 페이지로 안내한다. 번역은 기존 사용자 ON과 버전별 동의·예산 검증을 따른다. 사이트 권한 확대와 원문 전송 동의는 별개이며 업데이트 시 Chrome의 권한 확인이 필요할 수 있다.

0.11.0은 동일한 www.youtube.com 출처에서 `/watch?v=ID`와 `/shorts/ID`를 허용한다. Shorts는 가시 플레이어를 고르고 MAIN의 현재 URL·플레이어 응답 videoId 및 읽기 후 상태를 검증한다. 다음 영상 ID/문서 변경 시 세션을 종료하며 새 영상 자동 ON은 없다. UI 숨김은 전송 중지가 아니며 기존 ON 작업을 유지한다. 숨김 상태·자막 결과는 메모리에만 보관한다. 정적 `youtube-dom.js`는 영상 표면/ID 식별만 수행하며 키·자막·공급자 요청에 접근하지 않는다. 정책 schema v11은 지원 영상 종류를 반영하며 추가 호스트 권한이나 서버는 필요 없다.

0.11.1의 닫기는 UI 숨김이다. ON 작업/결과를 유지하며 OFF는 요청을 중단한다. 기존 패널의 로컬 복원은 새 번역 권한을 부여하지 않으며 번역 요청의 동의·모델 revision·문서 grant 검증은 그대로 적용한다. 페이지 MAIN world에는 복원 함수를 노출하지 않는다. API 키/권한/전송 범위/정책 schema v11은 변경하지 않는다.

0.11.2의 즉시 주입/단계별 대기 제한/로컬 표시 토글은 권한·동의·문서 grant·영상 ID 검사를 대체하지 않는다. UI 토글은 번역 전송 ON/OFF가 아니며 기존 ON 작업을 유지한다. 비디오 전용 모듈만 주입하고 초기화 실패의 불완전 상태를 제거한다. 추가 호스트·공급자 요청·로컬 서버는 없다.

0.11.3은 같은 문서/영상 ID의 media 노드 교체에 한해서 패널과 결과를 유지한다. 플레이어 안정화 중 새 자막 수집/번역을 쉬며 이미 시작한 요청의 결과는 기존 grant/ID 검사를 유지한다. 실제 영상 ID 변경/문서 종료는 계속 정리한다. 초기 자막 목록 재시도는 최대 3회이며 목록 메타데이터만 읽고 자동 번역은 시작하지 않는다. 원문/키/URL 진단 로그·새 서버·권한은 추가하지 않았다.
